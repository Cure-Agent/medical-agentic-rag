# 축 열거 프롬프트 — 생성층 결함을 지시만으로 회수할 수 있나

| | |
|---|---|
| 날짜 | 2026-08-23 |
| 커밋 | `18e4343` (미커밋 변경 0건, 각 `results/facet*/COMMIT`에 기록) |
| 반복 | **k=5** |

**판정: 도입하지 않는다.** +0.033, p=0.688.

## 가설

[repeat-k5](2026-08-23-repeat-k5.md)에서 분해의 이득이 검색층이 아니라 **생성층**에서
나온다는 것이 드러났다 — 근거를 풀에 쥐고도 놓치는 key point가 통제군 29건 대 분해 11건.

`answerer`는 **하위 질의를 보지 못한다.** LLM에 주는 것은 원 질문과 근거 풀뿐이다
(`app/agent/nodes/answerer.py`). 그러니 분해의 이득은 전부 풀 구성을 통해 간접 전달된 것이고,
answerer는 편중된 풀에서 밀린 축을 그냥 놓치고 있다.

> **질문**: 「질문의 축을 먼저 열거하고 축마다 답하라」는 지시만으로 그 놓침을 회수할 수 있나?
> 되면 LLM 호출 1회(분해)를 아낀다.

## 통제 조건

`rerank_facets`는 `rerank`에서 **`enumerate_facets` 플래그 하나만** 다르다. 검색 경로·LLM
호출 수·근거 개수가 전부 같아 차이가 나면 원인이 프롬프트로 특정된다.

`tests/test_facet_prompt.py`가 이를 잠근다:
- 기본 프롬프트가 이전 상수와 **바이트 단위로 동일**
- 검색 관련 필드 8개가 두 프리셋에서 동일
- 플래그가 실제로 answer 노드까지 **닿는지** — 이게 없으면 두 구성이 같은 프롬프트로 돌면서
  「차이 없음」이라는 잘못된 결론이 난다 (v1의 근거 개수 통제군에서 실제로 겪은 실패 유형)

프롬프트 델타는 `app/llm/prompts.py`의 `_ANSWERER_FACET_STEP` — 축 열거 + 「청크가 하나뿐인
축도 그 하나로 답한다」 + 「축이 하나라도 답되면 기권이 아니다」(과잉 기권 방지).

## 결과

| | `rerank` | `rerank_facets` |
|---|---|---|
| 정답률 | **0.600** | **0.633** |
| kp 커버리지 | 0.822 | 0.842 |
| 기권 (complex는 전부 answerable이므로 전부 오류) | 2/60 | **0/60** |
| 평균 답변 길이 | 514자 | 598자 |

- 정답률 차이 +0.033, CI [-0.100, +0.167], 부호검정 4:2 → **p = 0.688**
- kp 커버리지 차이 +0.019, CI [-0.053, +0.103], 부호검정 3:3 → **p = 1.000**

**지시는 작동했다** — 답변이 길어졌고(514 → 598자) 우려했던 과잉 기권은 오히려 줄었다
(2건 → 0건). 그런데 정답률이 움직이지 않았다.

### 왜 안 움직였나 — 층별 결함 크기

| 구성 | 근거 수 | 있음/담음 | **있음/놓침**(생성층) | **없음/놓침**(검색층) | 없음/담음 |
|---|---|---|---|---|---|
| `rerank` (운영, top-5) | 5 | 71% | **10%** (17) | 7% (11) | 12% (20) |
| `rerank_facets` | 5 | 72% | **8%** (13) | 7% (12) | 13% (22) |
| `rerank_topk11` | 11 | 72% | **18%** (29) | 2% (3) | 8% (14) |
| 분해 B (top-11) | 11 | 82% | 7% (11) | 1% (2) | 10% (17) |

축 열거가 회수한 것은 **17 → 13, 4건뿐**이다. 운영 구성(top-5)에서는 생성층 결함이 애초에
10%라 상한이 낮았다.

> 이 실험을 제안할 때 계산한 「상한 0.964」는 18%(29/165)에 근거한 것인데 그것은
> `rerank_topk11` 수치이지 운영 수치가 아니다. 그래서 실험을 `rerank`로 돌렸고, 결과는
> 운영에서의 상한이 그보다 낮다는 것을 확인해 주었다.

## 덤으로 나온 것

### 1. 근거 개수 통제군도 노이즈였다

| | v1 (k=1) | k=5 |
|---|---|---|
| `rerank` (top-5) | 0.50 | **0.600** |
| `rerank_topk11` (top-11) | 0.75 | **0.600** |

v1의 0.50 대 0.75는 재현되지 않는다. **기전까지 나왔다** — 위 표에서 top-5는 생성층 10%/
검색층 7%, top-11은 생성층 18%/검색층 2%로 **둘을 맞바꿔 같은 곳에 도달한다.** 컨텍스트를
늘리면 recall은 좋아지고 활용은 나빠진다.

운영이 이미 top-5이므로 **컨텍스트를 늘릴 이유가 없다**는 근거가 생겼다.

### 2. gold 라벨이 누락 편향돼 있다

「없음/담음」 12~13%(20~22건) 중 3건을 열어보니 **전부 라벨 누락**이었다. 예: cpx-004 kp1 —
인용 3개가 전부 풀 안에 있고 답변도 정확한데, 라벨러가 고른 gold 2개가 풀에 없었다. 같은
사실이 다른 청크에도 있는데 라벨러가 2개만 골랐다.

**즉 검색층 실패 7%는 과대 추정이다.** 라벨이 완전했다면 상당수가 「있음/놓침」으로 옮겨간다.
두 구성을 같은 gold로 재므로 비교 결과는 유효하지만 절대 비율은 신뢰할 수 없다.

## 판정

**축 열거 프롬프트를 도입하지 않는다.** +0.033은 CI 안이고 p=0.688이다. 기권을 2건 → 0건으로
줄이는 부수 효과는 무해하지만 그것만으로 채택할 근거는 아니다.

이로써 제안됐던 세 개입이 모두 기각됐다:

| 개입 | 효과 | 판정 |
|---|---|---|
| 분해 (변형 B) | +0.217, p=0.375 | 유의하지 않고 검색층에서 차이 없음 |
| 근거 증량 (top-11) | 0.000 | 재현 안 됨 |
| 축 열거 프롬프트 | +0.033, p=0.688 | 상한 자체가 작음 |

**검색 경로는 운영 현행 유지** — 원 질문 1개 → 하이브리드 → RRF 무절단 → 리랭커 → top-5 →
점수 게이트.

단, 이것은 「분해를 추가할 근거가 없다」이지 「현재 검색이 충분하다」가 아니다. complex
정답률은 0.600이고 cpx-010은 모든 구성에서 5회 내내 0/5다.
