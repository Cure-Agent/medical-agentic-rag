# 실험 기록

시점 증거 문서다. **한 실험 = 한 파일이고, 끝나면 관측 숫자를 고치지 않는다.**

새 실험이 이전 결론을 뒤집으면 새 문서를 쓰고 이전 문서 맨 위에 `superseded by` 배너를,
사실·통계 표현이 틀렸으면 `erratum` 배너를 추가한다. 숫자는 그대로 둔다 — 「1회 실행이
이렇게 틀릴 수 있다」는 것 자체가 증거다.

`results/` 원본은 gitignore이고 실행마다 덮어쓴다. 숫자는 문서 본문에 고정하고, 현재 판정에
쓰는 정답률은 [익명화된 공개 점수](evidence/paired_scores.csv)와
[검산 스크립트](../../scripts/verify_public_results.py)로 다시 계산할 수 있게 했다.

## 현재 판정 요약

**검색 경로는 운영 현행 유지** — 원 질문 1개 → 하이브리드 → RRF 무절단 → 리랭커 → top-5 →
점수 게이트. 제안된 **네** 개입은 모두 전면 도입 기준을 충족하지 못했다(숫자는
2026-08-24 교정본, 루프는 자체 문서):

| 개입 | 효과 (complex, k=5) | 판정 |
|---|---|---|
| query decomposition (변형 B) | +0.100 / +0.117, 부호검정 모두 4:3 | 이질성이 크고 검색층 효과도 +0.022, CI [−0.075, +0.144]로 불확실 |
| 근거 증량 (top-5 → top-11) | **−0.083 / −0.083** | CI [−0.267, +0.067]. 재현 안 됨 |
| answerer 축 열거 프롬프트 | **−0.067 / −0.083**, 부호검정 0:4 / 0:5 | 이득이 없고 방향이 반대일 수 있음 |
| 반복 검색 루프 (`rerank_full`) | +0.050, 부호검정 2:2 | CI가 0을 포함. 60행 중 12행만 루프에 진입했고 이득 대부분이 문항 1개(cpx-009) |

`/`로 나눈 값은 같은 파이프라인 출력에 대한 `grade-strict-v1` 채점 1·2회다. 루프는
1회만 채점했다. 과거 문서의 top-5 → top-11 `0.000`은 교정 전 값이고, 교정 채점에서는
두 회차 모두 `−0.083`이었다. 이 정정으로 판정은 바뀌지 않는다.

**에이전틱 개입 네 개에서 전면 적용을 뒷받침하는 일관된 이득을 얻지 못했다.** 이 결과는
「질문 구조가 병목이 아니다」라는 증명이 아니라, 현재 표본에서는 리랭커가 가장 큰 관측 효과를
보였고 추가 에이전틱 비용을 정당화할 증거가 부족했다는 제품 의사결정이다.

**유의성만으로 도입 여부를 정하지 않는다.** 불일치쌍이 5개인 비교에서는 모두 한쪽이어도
양측 부호검정의 최솟값이 p=0.0625지만, n=12 설계 자체가 원리적으로 유의할 수 없는 것은
아니다. 관측된 부호, 0을 포함하는 CI, 문항별 이질성, 검색층 기전과 비용을 함께 본다.

**강하게 남은 관측**(v1에서, 아직 k=1 근거 포함):
- 리랭커가 단일 최대 지렛대 (complex 0.17 → 0.50)
- 두 층 기권 게이트 — 검색 게이트는 *관련도*, 생성 게이트는 *답변가능성*
- 점수 게이트의 역할은 안전이 아니라 비용 절감

## 미해결

| 논점 | 상태 |
|---|---|
| **채점기 해시가 자동 기록되지 않는다** | `run_eval`은 결과 행에 `code_version`을 박지만 `judge`는 `judge_rules`(판 이름)만 박는다. 2026-08-24 채점은 해시를 사후에 적었다(`bc7a47b`). 다음 채점기 변경 전에 `judge.py`도 해시를 박게 고칠 것 |
| **gold 사람 검수** | 11 kp를 LLM(이 저장소 세션)이 검수했고 사람은 아직 안 봤다. 카드마다 근거 문장이 원문 인용으로 붙어 있어 확인은 빠르다 |
| ~~gold 라벨 누락 편향~~ | ✅ 해소. 전수 검수 결과 오라벨 5 kp·누락 3 kp였고, 「없음/담음」 73건 중 라벨 탓은 30건뿐이었다. 나머지는 채점 문제였고 등급 규칙으로 고쳤다 |
| **simple 카테고리 재채점** | 등급 명시 kp가 10개 있는데 등급 규칙 도입 후 재채점하지 않았다. simple 0.92는 구 채점 숫자다 |
| ~~리랭크 점수 컷 3.5 vs 9~~ | ✅ **운영에서 해소.** 2026-08-25 프로덕션 평가셋 229문항 × 2회 [컷 스윕](https://github.com/Cure-Agent/cure-agent-be/blob/dev/docs/rag-eval/2026-08-25-cut-sweep-verdict.md) 후 9 유지. 이유는 안전이 아니라 생성 호출 비용. 이 저장소는 `prod_rerank=9`, 과거 실험 재현용 `rerank=3.5`로 이름을 분리한다 |
| **기권 동작 재검증** | k=5 실행은 complex만 돌렸다. 구조화 기권 1.00은 k=1 결과 |
| **cpx-010** | 교정 후에도 모든 구성에서 5회 내내 0/5. 원인 미조사 |
| **루프 구성의 insufficient 손해** | `rerank_full`은 점수 게이트를 우회한다(배선상). complex에서는 무해했지만(점수 8~10이라 게이트가 걸릴 일이 없음) 무관 질문에서는 answerer 호출 + 재검색이 그대로 나간다. **재지 않았다** — 루프를 다시 볼 일이 생기면 insufficient부터 돌릴 것 |
| **루프의 흔들림 감소** | 흔들림 문항이 4 → 2로 줄었다. 정답률과 별개의 관측이고 k=5 한 판이라 재현 대기 |
| **`run_eval`이 usage를 기록하지 않는다** | 비용을 실측이 아니라 모델로 계산해야 한다(2026-08-24 루프 실험). 결과 행에 토큰 usage를 박으면 비용도 측정치가 된다 |
